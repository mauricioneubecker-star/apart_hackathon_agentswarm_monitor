## 2. Method

- **Unit of inference = config** (scenario_id). Replicates of a config share every factor and are strongly correlated (one-way ICC of `tipped` = 0.73, configs with >= 2 runs), so each config contributes one value: its tip rate (mean of `tipped` over its 1-3 control runs). Configs are weighted equally.
- **Marginal permutation test** per factor: the factor's labels are permuted across configs **within design block (split)**, 10,000 permutations. This reproduces the design: every night factor was drawn per block with fixed counts (`weighted_balanced`, independent shuffles; `generate.py` `gen_night`), model mix and tech-lead status iid. Statistic: binary factor = difference of the mean config tip rates (level - reference), two-sided p = (1 + #{|T*| >= |T|}) / (B + 1); multi-level factor = n-weighted between-level variance of the config means (equivalent to a permutation one-way ANOVA F), p = (1 + #{T* >= T}) / (B + 1).
- **Restrictions**: seed type is tested in the 4 blocks where it was randomized (night_branch is all `none`, night_test_ood_seed all `external`; 96 configs). Seed = tech lead only among knower/pioneer/side_task configs (64 configs), where it was a Bernoulli(0.5) draw.
- **Effect sizes**: tip-rate differences (percentage points, pp) or per-level rates with 95% percentile CIs from a **config-cluster bootstrap stratified by block** (2,000 resamples of configs with replacement within each block).
- **Multiplicity**: Holm over the 14 main factors (category, release_freeze, manager_push, discoverability, channels, self_merge, persistent_share, prohibition_form, n_impossible, persona_mix, sanctions, model_mix, seed_type, seed_tech_lead). Post-hoc pairwise contrasts: Holm within factor. Extra design factors (seed placement, cut, push offset, family, effective enforcement): own Holm family, exploratory.
- **Multivariable model**: logistic regression of run-level `tipped` on all 14 factors (one-hot) plus block dummies, 26 parameters, Newton-Raphson with L2 lambda = 1/C, C = 1e6 (= sklearn `LogisticRegression(C=1e6)`, checked). References: category = K2, release_freeze = False, manager_push = False, discoverability = peers_only, channels = team_channels, self_merge = False, persistent_share = 0.0, prohibition_form = soft, n_impossible = 9, persona_mix = uniform, sanctions = off, model_mix = duo, seed_type = none, seed_tech_lead = False, split = night_train. Odds-ratio CIs from the stratified config-cluster bootstrap (2,000). Because unpenalized refits separate in many resamples (below), the same resamples are also refit with **Firth's bias-reduced logistic regression**. **Adjusted randomization test** per factor: permute that factor's labels across configs within block, keep all other factors fixed, refit; statistic = likelihood-ratio (deviance drop) of the factor's columns; 10,000 permutations; exact under the sharp null because the factors were assigned independently. Holm over 14.
- **Adjusted risk differences** (no separation issue): OLS of the config tip rate on the same design (112 configs, equal weights; sensitivity with run-count weights), randomization test = partial F (extra sum of squares) with the same within-block permutation, 10,000 permutations; stratified config bootstrap CIs (2,000).
- Seed type in the adjusted tests is permuted jointly with tech-lead status (joint null of the seed design); tech-lead status alone is permuted within block x seed type.
- **Interactions** only exploratory: 2x2 config-level cells, difference in differences (DiD) with bootstrap CI, and subgroup permutation tests (effect of A within each level of B, permuted within block; uncorrected).
- **Row-level contrast**: Fisher / chi-square tests on runs and the asymptotic chi-square p of the run-level LR are shown only to illustrate why they are anti-conservative here (runs within a config are not independent). DeLong is not applicable (no AUROC in this question).

## 4. Multivariable model (all factors jointly)

Full data: 236 runs, 93 tipped, 26 parameters. **No separation on the full data**: max |beta| = 2.79, coefficients change by at most 1.2e-05 when C goes from 1e6 to 1e10, no one-hot column with all-0 or all-1 outcomes, Hessian condition number 634, sklearn `LogisticRegression(C=1e6)` agrees to 8.5e-07. **But 37.2% of the 2,000 cluster-bootstrap refits have some |beta| > 10** (quasi-separation inside resamples: 26 parameters, about 112 independent units, ICC 0.73). ## 7. Controls and sanity checks

- **Identical-design blocks** (night_train, night_val, night_test_id were generated by the same recipe): tip rates night_train 35.2%, night_val 16.7%, night_test_id 50.0%; permutation test of the block label p = 0.19. The low night_val rate is within chance.
- **Replicate order / time-of-night drift**: rep0 36.5% vs rep1 40.4% in 104 configs, sign-flip p = 0.43; concordant 33 both tipped, 57 neither, discordant 5 + 9. rep2 vs mean(rep0, rep1) in 20 configs: +2.5 pp, p = 1.00.
- **Within-config correlation**: ICC = 0.73 (104 configs, 228 runs); design effect about 1 + (2.19 - 1) x 0.73 = 1.87.
- **Null calibration of the permutation test**: 2000 placebo factors drawn like a 50/50 night factor: share p < 0.05 = 0.0415, p < 0.01 = 0.0105, mean p = 0.519 (slightly conservative because config tip rates take few distinct values; ties count as extreme).
- **Row-level tests are anti-conservative**: seed placement looks significant per run (Fisher p = 0.016) but not per config (permutation p = 0.20); n_impossible chi2 p = 0.030 vs 0.0840; tech lead Fisher p = 0.083 vs 0.20.
- **Reproduces the batch report** (`runs_night/_logs/report.md`, written at 239 runs): run-level rates K2 23.7% / K4 55.1% (report 23 / 54%), freeze off/on 18.6% / 48.2% (20 / 46%), peers_only/exploration 23.7% / 55.1% (21 / 56%), board/team/dm 53.2% / 23.7% / 11.1% (52 / 23 / 11%), sanctions off/drawn 39.5% / 39.0% (37 / 42%).

## 9. Caveats

- 112 configs, 236 runs, ICC 0.73: the effective sample size is close to the number of configs. Effects below about 20-25 pp are hard to detect, especially for factors with small cells (dm_only 17 configs, no freeze 33, detection > 0 only 8).
- The design is balanced per block and the factors were drawn independently (fixed counts per block, independent shuffles), so marginal differences are unbiased for the average effect over the other factors' design distribution. Chance imbalances still exist in a single draw (freeze configs: 43/79 K4 and 52/79 board; no-freeze configs: 13/33 K4 and 15/33 board), which is why the adjusted freeze effect is smaller than the marginal one.
- Effects are averages over this design (high pressure, R = 30, tech lead, merge feed with CI status, release board, 4 training models). They do not transfer automatically to other settings; the night batch has no 'hard' prohibition form and no skewed_careful personas.
- The FINDINGS sentences were written after looking at the batch report, so the tests are confirmatory only in the sense of being corrected for all 14 factors. Freeze was the pre-stated base-rate dial of the design (DECISIONS.md section 15, pilot 4: 0/14 without freeze); as a single pre-specified hypothesis its uncorrected p = 0.0048 would apply.
- The multivariable logistic model is fragile (26 parameters, about 3.6 events per parameter, quasi-separation in bootstrap resamples); use it for direction and the adjusted randomization p-values, not for the size of the ORs.
- The interaction findings are exploratory (not pre-specified, not corrected). The discoverability x category interaction is large and has a mechanistic explanation in the generator code, but it should still be presented as a post-hoc observation.
- seed type `external` pools fake_authority and injection (doc / issue_comment); the tool_output carrier only appears in night_test_ood_seed and is excluded from the seed-type test.
